1. Difference Between port, targetPort, and nodePort
In Kubernetes, when you define a Service (especially of type LoadBalancer or NodePort), 
these three port fields govern how external and internal traffic flows into your pods:

* port (Service Port):

What it is: The virtual port on which the Service itself listens inside the cluster.

Purpose: Other pods within the cluster use this port to communicate with your service (e.g., http://mongo-express-service:8081).

* targetPort (Container Port):

What it is: The port on which the actual application container is running and listening inside the Pod.

Purpose: Once the Service receives traffic on its port, 
it forwards that traffic to this specific targetPort on the matching pod. 
In your YAML configuration, both are 8081.

* nodePort (Node Port):

What it is: A static port allocated 
in the background on every node's IP address (Worker Node) within the specified range (30000-32767).

Purpose: It allows external traffic from outside the Kubernetes cluster 
to access the service by hitting <Node-IP>:<nodePort>. Your configuration allocates port 30100.

* kubernetes: The default internal service for the Kubernetes API server. 
It runs as a ClusterIP on internal IP 10.96.0.1 and listens securely on port 443/TCP.

* mongo-express-service: Your newly created LoadBalancer service.

CLUSTER-IP (10.96.205.154): The internal virtual IP assigned inside the cluster.

EXTERNAL-IP (<pending>): Shows <pending> because Minikube runs locally 
on your machine rather than a cloud provider (like AWS, GCP, or Azure), 
which means it cannot automatically provision a real external cloud load balancer.

PORT(S) (8081:30100/TCP): Displays the mapping where 8081 is the Service port and 30100 is the nodePort.

* mongodb-service: An internal ClusterIP service handling database traffic on internal IP 10.110.35.151 and port 27017/TCP.

3. Minikube Service Command
Is it required to execute minikube service mongo-express-service?
Yes and no. It is not strictly required if you already know 
how to reach the node IP directly, but it is heavily recommended and the easiest way 
on local environments like Minikube. 
Because Minikube runs inside a virtual machine or Docker container on Windows, 
its LoadBalancer external IP stays <pending>. 
Running minikube service bridges that gap so you can easily open it in your browser.

What does minikube service mongo-express-service do?
It inspects the specified service, 
figures out how to reach it from your host machine, 
sets up any necessary network routing or tunneling, 
and can automatically launch your default web browser to the correct address.

1. Direct Node URL ([http://192.168.49.2:30100](http://192.168.49.2:30100)): 
Minikube first identifies the internal node IP (192.168.49.2) 
and combines it with your configuration's nodePort (30100).

2. Tunneling ([http://127.0.0.1:57658](http://127.0.0.1:57658)): 
Because you are running Minikube on Windows (likely using the Docker driver), 
your host machine cannot always route directly to internal Minikube bridge IPs seamlessly. 
Minikube automatically starts a local network tunnel (minikube tunnel) 
mapping a localhost loopback port (127.0.0.1:57658) straight to the service.

3. Browser Launch: Minikube attempts to pop open your default web browser 
using that local proxy URL so you can log into Mongo Express right away.
(default: 'admin' / 'pass' for the Mongo Express Image)
